# Changelog

## v1.14.5

- исправлено: при `useExtBalancer` документ `KubeAPIServerConfig` (certExtraSANs) попадал в конфиги worker, а он разрешён только на control plane; теперь он только в `cpN.patch`

## v1.14.4

- `imageCache: true` теперь добавляет и `ImageCacheConfig` (`local.enabled: true`): без него Talos не использует кэш из ISO и тянет образ по сети

## v1.14.3

- добавлены ключи `imageCache` и `imageCacheSize`: том `IMAGECACHE` (VolumeConfig) для копирования image cache из ISO на диск при установке, только Talos >= 1.14

## v1.14.2

- добавлен ключ `extraHosts`: записи /etc/hosts на нодах (Talos >= 1.14 — StaticHostConfig, 1.12/1.13 — `machine.network.extraHostEntries`)

## v1.14.1

- версионирование утилиты теперь привязано к мажору talosctl: v1.14.x соответствует Talos 1.14
- добавлены ключи `httpProxy` и `noProxy`: прокси для нод (Talos >= 1.14 — документ EnvironmentConfig, 1.12/1.13 — `machine.env`); `no_proxy` автоматически включает подсеть нод, pod/service CIDR, VIP, балансировщики, `.svc` и `.cluster.local`

## v1.6.1

- **ключ `downloadImage` удалён**: Talos всегда тянет installer-образ из реестра, режима «использовать загруженный образ» нет, ключ только убирал строку из конфига
- добавлен ключ `installerMirror`: зеркало реестра для installer-образа (factory.talos.dev), для установки без выхода в интернет (образ должен лежать в зеркале)

## v1.6.0

- версия куба 1.37.1
- версия talos 1.14.4
- **поддерживаются только Talos >= 1.12.0**: обратная совместимость с версиями < 1.12.0 удалена (hostname всегда в документе HostnameConfig)
- Talos >= 1.14: патч генерируется новыми документами (UnattendedInstallConfig, ResolverConfig, TimeSyncConfig, RegistryMirrorConfig, CRICustomizationConfig, KubeletConfig, KubeAPIServerConfig, удаление KubeFlannelCNIConfig/KubeProxyConfig), иначе `talosctl validate` падает на конфликте с v1alpha1-полями; для 1.12/1.13 формат прежний
- `talosctl gen config` теперь вызывается с `--talos-version` из образа: формат конфига соответствует версии образа, а не talosctl
- команда `add` учитывает образ из UnattendedInstallConfig и переносит доп. документы патча (KubeletConfig и т.д.)
- исправлена генерация: `error decoding document ... mapping key "apiVersion" already defined` — разделитель документов определялся по подстроке `---\n` и ломал PEM-ключи (`-----END EC PRIVATE KEY-----`)
